# 引力弹弓 · 星驿快递（GravitySling）

把房间变成地月系：捏住探测器向身前拉，像拉弹弓一样发射，借助天体的引力弯曲轨道，把包裹送到空间站。

## 玩法

核心动作是拉弓发射，借天体引力弯曲航线。在这之上有四层变化，让 18 关不只是「换个角度再拉一次」：

- **飞行中点火**（第二章起）：松手后不只是旁观。飞行途中捏一下手指，探测器沿当前方向加速 35%，每次飞行限一次。飞行时有一条橙色虚线，显示「现在点火」会走的航线，玩家看着它扫过目标时再捏。在擦过行星、速度最快的时候点火效果最明显，对应真实的奥伯特效应（图鉴「轨道修正」）。普通关不点火也能拿满三星；点火是补救失误或走捷径的技巧。
- **挑战关**（每章一关）：本章 5 关全部送达后解锁，不影响进入下一章。第一章的挑战要摆好引力球去追一座绕地球运行的空间站，必须算好提前量；第二、三章的挑战没有点火送不到。
- **可选引力球**：2-1、3-1 在发射架右边多放了一颗引力球（1-2 原来也有，v1.3 去掉了：玩家第一次见到引力球，应该是在专门教它的 1-3）。放在架子上时它是关着的（只剩内核，不吸引也不会被撞），不用它也能按原来的路线通关；把它放出来，就能找到别的航线。
- **盲射挑战**：15 个主线关全部送达后开放。打开后不显示瞄准线、点火航线和标准航线，送达就能拿到这一关的 ◆ 徽章。
- **立体星图**：送达后，主场景里会浮现一张星图。每章一个星团，围着本章的行星，每关一颗星：灰色是未解锁，青色在呼吸的是可以去的，金色是已送达（下方的小点是拿到的星数），紫色菱形是挑战关，白圈是当前关，紫圈是盲射徽章。捏住一颗星就直接去那一关；一开始拉弓就自动收起。控制台的选关按钮仍然保留，两边同步。

### 首次引导

拉弓的新手引导之外，三个后来才出现的动作各有一次手把手引导，玩家做过一次就不再出现。提示放在主场景里、紧挨着要操作的东西，因为玩家这时看的是场景，不是控制台；每条提示牌都带一个「捏合」小动画。

| 动作 | 什么时候出现 | 场景里 | 控制台 |
|---|---|---|---|
| 摆放引力球 | 第一次遇到有引力球的关（1-2 起） | 引力球轻轻呼吸，一颗半透明的示范球反复从架子上被拖出去；球上方的提示牌写「捏住引力球，拖到空中」 | 「新技能 · 引力球」卡片 |
| 飞行中点火 | 第二章起，玩家第一次点火之前的每次飞行 | 飞行途中时间放慢到 15%（约 3 到 4 秒），橙色虚线闪烁，探测器上方的提示牌写「捏一下手指 = 点火」，捏这块牌子也能点火 | 「新技能 · 点火」卡片；慢动作时状态栏提示「现在捏一下手指，点火！」 |
| 星图选关 | 星图出现时，直到第一次从星图选关 | 星图上方的提示牌写「捏住一颗星，去那一关」，下一关的星星脉动得更明显 | 原有的一行说明 |

慢动作的时机由程序按这一发算出：优先选在探测器擦过行星、离它最近的时候（这时点火最划算，就是奥伯特效应）；没有擦过行星时选在起飞 1 秒左右。不管选在哪里，都先验证「这时点火不会把这一发搞砸」：原本能送达的一发，点火后还得能送达；原本送不到的一发，点火后不能变成撞毁。找不到这样的时刻（比如 2-4，那一发怎么点火都会错过空间站），这一次就不放慢，等下一次飞行。慢动作只放慢时间，不改变物理，飞行结果和不放慢完全一样。

用到的空间特性有五项：
- 3D 体积内容
- 手势拉弓和拖动
- MR：切到「环境：房间」时能透视看到真实房间
- 多窗口联动
- 空间音频：行星低鸣按位置发声，各种音效从事件发生的位置传来，背景音乐环绕播放

## 音效

全部由 `tools/sfx.py` 用程序合成（48kHz 单声道），不用外部素材，也就没有授权问题。共 8 个：

- 行星低鸣
- 拉弓
- 发射和加速
- 收集星星
- 穿过中继环和虫洞
- 送达
- 坠毁
- 放下引力球

背景音乐不再程序合成。原来的合成背景声在小扬声器上只剩一个 880Hz 的持续单音，听起来很刺耳，已经删除；背景音乐改用 CC0（公有领域）曲库里的现成曲目，候选和授权记录见 `docs/音乐候选/`。选定的曲子放在 `assets/audio/bgm.ogg`，用安卓原生播放器无缝循环（背景音乐不需要空间定位，这是 SDK 文档推荐的低开销做法），应用切到后台时自动暂停。

每个音效有一个常驻的发声实体，播放时只移动位置、重新开始播放，以避开 SDK 文档提到的「频繁创建短音效导致掉帧」的问题。

## 关卡（3 章 × 5 关，外加每章一个挑战关）

最后两列是标准解法在手抖 ±1.5 cm 下的送达率（v1.3 放大签收范围前 → 后）；需要点火的关，同时让点火时机随机早晚 0.1 秒。`LevelsTest` 的设计报告还会打印 ±3 cm 下的送达率。

| 关卡 | 教学点 | 送达率（前 → 后） |
|---|---|---|
| **第一章 月港** | | |
| 1-1 首单 | 拉弓发射 | 45% → 100% |
| 1-2 月影 | 借月球引力绕到背后 | 46% → 84% |
| 1-3 借力 | 自己摆放引力球（v1.3 重新设计） | 43% → 100% |
| 1-4 月背中继 | 先过中继环，再「回旋镖」绕回来 | 44% → 90% |
| 1-5 追月 | 运动的月球 | 54% → 81% |
| 1-6 追站（挑战） | 摆好引力球，追上绕地球运行的空间站（要算提前量） | 72% → 72% |
| **第二章 赤色航线** | | |
| 2-1 赤色门户 | 陨石带：找到缺口穿过去（可选引力球；从这关起可以点火） | 64% → 100% |
| 2-2 加速环 | 速度不够，必须先穿过加速环 | 40% → 64% |
| 2-3 双卫 | 火卫一、火卫二反向转动，从中间穿过 | 65% → 79% |
| 2-4 穿针 | 用引力球把轨道勾回陨石墙后面 | 44% → 69% |
| 2-5 火星快线（章末） | 加速、绕到火星背后过中继环、折返 | 25% → 34% |
| 2-6 弹弓失灵（挑战） | 发射架力气不够，贴着火星掠过时点火 | 43% → 43% |
| **第三章 深空邮路** | | |
| 3-1 巨行星 | 借木星的强引力转大弯（可选引力球） | 72% → 88% |
| 3-2 虫洞 | 从虫洞穿到木星背后 | 91% → 99% |
| 3-3 伽利略卫星 | 三颗运动卫星组成的「旋转门」 | 84% → 98% |
| 3-4 双球 | 两颗引力球，走 S 形航线 | 36% → 46% |
| 3-5 回家（终章） | 加速、绕木星、过中继环、钻虫洞回到总部 | 41% → 42% |
| 3-6 近木点火（挑战） | 落向木星，近木点点火甩出去，躲开木卫二 | 36% → 36% |

测试要求：普通关的送达率不低于 35%，第二、三章的章末关和挑战关不低于 25%。

每一关的设计流程：
1. 用 `tools/levellab.py` 搜索弹道，再用局部优化提高送达率。
2. 把结果写进 `Levels.kt`。
3. 由 Kotlin 测试做最终验证。测试会检查：
   - 标准解法能拿满三星；
   - 加速环和虫洞都用上了，而且缺了它们就拿不到三星；
   - 引力球的摆放位置合法；放在架子上的引力球完全不起作用；
   - 2-1、3-1 的可选引力球确实能开出别的航线（存在只有放了球才送得到的发射方式）；
   - 挑战关缺了自己的门道就过不去：2-6、3-6 随机发射 4000 次，不点火一次也送不到（没有点火时，能量守恒把探测器限制在离行星约 1 米以内，空间站在这个范围外）；1-6 不放引力球就拿不到三星；
   - 预测轨迹和逐帧实际飞行一致，「现在点火」的预测线和真正点火后的航线也一致。

挑战关是用 `DesignLab`（`./gradlew testDebugUnitTest --tests '*DesignLab*' -Dlab=design`）搜出来的：大量随机发射，只留下满足上面条件、而且手抖下仍然稳的方案。

图鉴共 20 张卡片，每关解锁一到两张（1-1 解锁小驿号和地球，2-1 解锁火星和探测器家族），内容是可以核实的科学知识和史实，新卡的数字出处见 `docs/知识产权.md`。每张卡有一句「最有意思的事实」，送达时显示在控制台上。只有一处虚构：游戏里的火卫一、火卫二反向转动，卡片上有说明。

每关有 3 颗星。星星都放在标准航线上，所以按标准航线飞就能拿满三星。玩家可以随时打开「看标准航线」作为提示。

## 画面

Spatial Editor 只有 Windows 和 macOS 版，这个项目的场景、灯光和特效都在代码里完成：

- **每章专属环境**：第一章是蓝色银河，第二章是暗红星云，第三章是琥珀色星云和淡紫色星团。换关时天空、环境光（IBL）、主光和轮廓光的颜色一起切换（`render/Lighting.kt` 的 `ChapterLook`）。
- **环境光**：舞台是混合模式（为了能切到真实房间），系统默认用摄像头看到的房间给 PBR 模型打光，金属探测器会映出卧室。所以模型用本地 IBL 接收星空的光（`render/Lighting.kt`）；切到「环境：房间」时再混入 70% 的房间光。
- **大气和光晕**：只渲染背面的叠加发光球壳。行星挡住中间，只在轮廓处留下一圈光，不需要自定义着色器（`Shapes.kt` 的 `rim()`）。
- **粒子**：收集星星、加速、穿过中继环和虫洞、送达、坠毁各有一组火花；飞行时探测器后面有离子尾流。用实例化网格绘制，每种颜色一次绘制调用（`render/Effects.kt`）。
- **星尘**：游戏区周围漂浮着 160 颗暗淡的尘埃，转头时能感到空间的远近。整团星尘一起缓慢旋转，每帧只更新一个变换。
- **动画**：关卡开场时天体依次弹出，然后星星出现；发射台、加速环和虫洞上的光点会旋转。

## 模拟器自动测试（仅 debug 版）

没有手部追踪也能跑完整流程：通过 adb 发广播，游戏会用每关的标准解法自动发射，结果写进 logcat（标签 `GravityTest`），每次飞行一行 `result`（结果、星数、帧率、最慢一帧），最后一行 `done` 汇总。

```bash
B="adb shell am broadcast -a com.vrgames.gravitysling.TEST -p com.vrgames.gravitysling --es cmd"
$B all                  # 18 关（含挑战关）连续自动通关，需要点火的关会在标准解法的时刻自动点火
$B level --es id 2-3    # 只跑一关
$B shot                 # 当前关发射一次
$B reset                # 清空存档和新手引导，重新体验首次游玩
$B mute --es id hum     # 静音某一类声音：hum / sfx / music / all，none 恢复
$B view --es id "0,1.4,-0.9,0,0.6"   # 把游戏区挪到模拟器固定视角前面（x,y,z,偏航角,缩放），reset 复原
$B slow --es id 0.05    # 慢动作，方便截到短暂的特效；1 复原
$B ibl --es id 9        # 调星空环境光亮度（指数，SDK 默认 8）
$B miss                 # 故意朝最近的行星发射，看坠毁特效
$B sky --es id 0        # 0 切到房间（透视），1 回到星空
$B nrm --es id 2        # 调月球/火星法线贴图强度（1 为默认）
$B sun --es id "1100,-35,50"   # 调主光（太阳）：照度 lux，可选俯仰角、偏航角
$B sph --es id 0        # 月球/火星改用引擎自带球体（对比用，下一关生效），1 恢复
$B map --es id 1        # 显示立体星图（0 收起）
$B pick --es id 2-3     # 相当于在星图上捏住 2-3 那颗星（未解锁时只记一行 locked）
$B blind --es id 1      # 打开盲射挑战（0 关闭）
$B burn                 # 飞行中立即点火，相当于捏一下手指
$B coach                # 重看新手引导和全部首次引导（不清存档）
$B coach --es id hints  # 只重看三个首次引导，跳过拉弓教学（模拟器上没法捏，教学走不完）
$B guide --es id 1      # 打开控制台的「玩法说明」（0 收起）
$B coachshot            # 像玩家一样发射当前关：点火引导会放慢，不自动点火（再发 burn 模拟捏手指）
adb logcat -s GravityTest
```

正式版（非 debuggable）不会注册这个入口。

## 上机后需要优先验证

- **首次引导（v0.6 新增）**：
  - 场景里的提示牌（SDK 的 AttachmentPanel）能不能正常显示、是否朝向玩家、字的大小（设计为字高约 2.2 厘米）。
  - 点火引导的慢动作节奏：放慢到 15%、约 3 到 4 秒，是太长还是太短（`GameSession` 里的 `CUE_SLOW`、`CUE_HOLD`）。
  - 捏点火提示牌能不能点火；在别处捏能不能点火（两种都应该可以）。
  - 引力球的提示牌在球上方 7 厘米，确认它不会挡住捏球。
  - 星图的提示牌离玩家比游戏区远，模拟器上看起来比另外两块小，真机上确认字看得清；看不清就把 `CoachLabels.kt` 里星图那块单独放大。新装的游戏第一次打开星图时，下一关的星星应该一闪一闪（模拟器存档已全部通关，没机会看到）。
  - 模拟器上没法捏，所以「捏住引力球就算学会」「捏提示牌点火」这两处交互只能在真机上验证。
- **点火和星图（v0.5 新增）**：
  - 飞行中捏一下手指能不能稳定触发点火。点火区是一个罩住游戏区的透明碰撞盒（只在飞行中、还能点火时打开），要确认它被识别为可捏的目标，同时不会挡住控制台按钮。
  - 星图离玩家约 1.2 米、高出发射架约 0.4 米，星星直径约 2.6 厘米，可捏范围半径 3.2 厘米。确认看得清、捏得准，必要时调 `render/StarMap.kt` 里的 `CENTER`、`STAR_R` 和碰撞半径。
  - 1-6 的空间站会动：它在发射前停在起点，发射后才开始绕地球转。确认玩家能理解「要提前量」，不理解的话考虑在瞄准时也让它转起来。

0. 画面（v0.4 新增）：星空环境光的亮度（`ibl` 调试命令可实时调，默认指数 9）、行星大气光圈和引力球光晕的强度、火花和星尘在头显里的大小。模拟器截图见 `docs/画面截图/`。

   - 太阳光：模拟器上方向光对模型几乎没有作用（太阳从 0 调到 20 万 lux，月球亮度只变了不到 1/255，画面亮度几乎全来自星空环境光）。上机用 `sun` 命令试一下：如果真机上也没作用，就把主光的阴影关掉（省性能）；如果有作用，再调出明暗交界线。

1. 拖拽位移的换算（`dragAmount` 从 px 换算成米）在近处捏合和远处凝视捏合两种方式下是否都跟手。
2. 场景原点（离地 1.15 米、玩家前方 1 米）站着和坐着是否都合适。控制台有「升高」「降低」按钮可以调。
   - Swan 以坐姿和小幅度站姿为主。1-3 的引力球参考位置离停放处约 45 厘米（v1.3），坐着应该一次拖得到；后面的关卡离得更远时，如果要松手再捏好几次，就在 `Playfield.drag` 里按距离放大手的移动。
3. 天空球的朝向和亮度，地球和月球的光照。
4. 体积窗口（图鉴）里模型的大小。
5. 帧率：每帧 360 Hz 物理步进，加上瞄准线的实例化渲染。

## 下一步

- 上机后：首次运行排查崩溃，然后调手感（拖拽灵敏度）、音量平衡、场景高度、帧率。
- 模拟器上冷启动常被系统判为「没有响应」并杀掉：SDK 的 ARM 原生库在 x86 模拟器上要转译加载 13 到 27 秒，超过了系统的启动时限，同一台模拟器上的其他应用也一样。游戏自己代码里的主线程阻塞（同步准备背景音乐、主线程解码贴图）已经改掉；真机上要确认冷启动是否顺畅。
  在模拟器上把游戏设成调试应用，系统就会跳过这个检查（只影响这一个应用，`adb shell am clear-debug-app` 撤销）：
  ```bash
  adb shell am set-debug-app --persistent com.vrgames.gravitysling
  adb shell am start -n com.vrgames.gravitysling/.platform.LaunchActivity
  ```
- 模拟器上的帧率（约 1 帧/秒）和偶发的 1 到 6 秒卡顿由模拟器本身的负载决定：同一关两次搭建可以差 5 倍，对照关 1-4 也有同样的卡顿，静音后也不变。真机上看 logcat 里每关的 `build` 行（分段耗时：清理上一关、天体、其余、光照、复位）和 `result` 行的 `worst`。

## 体验流程

1. **片头**：控制台显示标题「引力弹弓 · 星驿快递」和免责声明。按钮是「开始第一单」，有存档时是「继续派送」。
2. **新手引导**（只在第一次游玩时出现）：
   - 控制台分三步提示：捏住、往身前拉、松手。
   - 主场景里有一个半透明的示范球，反复演示往身前拉的动作，玩家第一次拉动后消失。
   - 之后第一次遇到引力球、点火和星图时，各有一次场景里的引导（见「首次引导」）。控制台右上角的「玩法说明」随时可以查全部手势，也能重看引导。
3. **关卡**：拿满三颗星送达时，空间站上方会放出金色星屑。
4. **送达后**：控制台列出新解锁的图鉴卡和一句最有意思的事实，可以直接打开图鉴；主场景浮现立体星图，捏一颗星就去下一关。
5. **章节结算**：每章最后一关送达后，控制台显示本章的星数，可以直接前往下一章或打开图鉴；本章的挑战关同时解锁。
6. **全部通关**：显示总星数和结语，盲射挑战开放。
